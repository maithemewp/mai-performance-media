- Give unsized local images their real width and height on the finished page. Raw `<img src alt>` tags with no `wp-image-<id>` class (pasted or imported classic content) get no width, height, srcset or lazy loading from core (`wp_filter_content_tags()` needs the ID for size and srcset, and `wp_get_loading_optimization_attributes()` skips anything without both dimensions), and `LoadingAttributes::decide()` skips them on purpose. So each one downloads in full at page start and competes with the main image. In `walk_page()`, when an image's src is under the uploads URL and the file exists, read its size with `wp_getimagesize()` and add `width` and `height`, then decide as usual. Cache the size per URL, and measure the file read on a site without a page cache. Don't look up the attachment ID: `attachment_url_to_postid()` took about 0.5s per image warm on a large site. No srcset without an ID, so huge originals stay full size but load lazily. Mai Engine sets `img { height: auto }`, so the attributes won't stretch images. Seen on an ad-heavy site, 2026-11-17: blocking two such images on one article cut lab LCP from 3.6s to 2.9s.
